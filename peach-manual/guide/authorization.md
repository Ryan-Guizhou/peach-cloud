# 授权与数据权限

本页面向 **系统管理员**，说明 Peach Cloud 中与访问控制相关的配置路径与推荐顺序。

## 核心概念

| 概念 | 作用 |
| --- | --- |
| 机构 | 数据与权限隔离边界 |
| 用户 | 登录主体，可关联多个机构 |
| 角色 | 权限集合载体 |
| 菜单 / 路由 | 控制左侧导航与页面入口 |
| 资源 | 页面按钮、接口等细粒度权限码 |
| 数据权限 | 控制业务列表/详情的数据可见范围 |

## 推荐配置顺序

```text
1. 机构管理 → 建立组织树
2. 用户管理 → 创建账号并关联机构
3. 角色管理 → 定义角色
4. 菜单 / 路由 / 资源 → 确保元数据完整（通常由实施或研发初始化）
5. 角色授权 → 绑定菜单、按钮资源
6. 角色授权 · 数据权限 → 配置 DataScope 规则
7. 验证 → 目标用户切换机构或重新登录
```

## 角色授权页面（/authorization）

授权管理页通常包含三个维度（以当前界面 Tab 为准）：

### 按角色授权

为角色分配：

- 可访问菜单
- 可使用的按钮 / 接口资源

### 按用户授权

在角色之外，对单个用户做补充或例外授权（视业务策略使用）。

### 数据权限

为角色或用户配置 **DataScope**：

- 选择模块（`moduleCode`）
- 选择范围类型（如本机构、本机构及下级、仅本人、租户全域等）
- 必要时指定组织范围

配置保存后，后端会刷新登录权限缓存；**用户需切换机构或重新登录** 才能看到最新数据范围。

## 权限验证清单

部署或变更后，请逐项确认：

- [ ] 目标用户在右上角能看到正确机构
- [ ] 左侧菜单包含预期入口
- [ ] 页面内按钮显隐符合角色
- [ ] 列表数据量 / 范围符合数据权限
- [ ] 授权日志中有对应变更记录（见 [日志与审计](/guide/logs-and-audit)）

## 常见配置失误

| 现象 | 常见原因 |
| --- | --- |
| 有菜单但按钮灰色 | 资源码未授权 |
| 有按钮但接口 403 | API 资源与菜单授权不一致 |
| 列表为空但不应为空 | 数据权限过窄 |
| 切换机构后仍不对 | 未触发权限快照刷新 |
