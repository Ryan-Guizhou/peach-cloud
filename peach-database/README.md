# Peach Database

[English](README.en-US.md)

JDBC 应用共享的 MySQL 初始化模块。项目尚未上线，现已整理为一个完整 Flyway V1：直接执行打包的 `ALL_TABLE_CREATE.sql` 与 `INIT.sql`，不在版本内部重放历史升级链。

## 开发库启动

配置新的空开发 schema，按原数据源配置启动应用。V1 创建完整当前结构、27 个页面路由、菜单与功能关联、管理员授权及 M/F/RT/RL 四位编码。资源共有 257 项：255 项明确控制台定义，加上保留的平台登录日志与路由删除权限；资源鉴权标识保持不变。四种编码规则及持久发号账本已初始化；新库没有历史编码映射表。

种子完全来自执行仓库系统脚本的隔离空库，不复制实际业务库记录。原有开发默认账号凭据契约保留，暴露开发环境之前应修改默认凭据；文档不展示凭据值。

## 现有本地数据库

本次首版与旧开发迁移历史（包括 V14）不兼容。不得自动 clean、repair、删除历史或重新 baseline 现有数据库。先备份需要保留的本地数据，再配置新的空 schema，仅重新录入经过核对的开发数据。无版本的非空库，以及旧 BASELINE 或已执行其他版本的库，都会在迁移前明确拒绝。仓库文件修改不会变更现有本地业务库。

MySQL 命名锁串行化多应用初始化。Hikari `maximumPoolSize` 至少为 3。迁移失败阻止启动；DDL 可能独立提交，因此首次初始化失败可能留下部分结构，应检查失败原因后使用新的空开发 schema。自动 clean、repair 均被禁用。成功后重复启动只验证校验和，不覆盖用户修改。

## 首版维护

修改 `sql/` 下单表文件和 `sql/INIT.sql` 后，在仓库根运行：

```bash
node scripts/sync-database-sql.mjs
node scripts/verify-changes.mjs
```

生成器同步聚合 schema 与 Docker 初始化镜像。`sql/migrations/` 中的手工脚本仅作历史参考，不是启动步骤。运行时不再扫描 V2—V15 升级链。首次真正发布后冻结 V1，后续变更新增向前迁移。

验证使用 JDK 21 与隔离 MySQL schema，覆盖完整初始化、引用与 API 授权、四位发号及耗尽、重复与并发启动、校验和及 SQL 失败保护、旧历史拒绝和 Boot 装配。集成测试只清理自身生成的测试 schema。
