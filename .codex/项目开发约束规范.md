# Peach Cloud Codex开发约束规范（V1）

> 目的：约束 Codex在本仓库实现功能时，代码风格、分层边界、命名方式与现有工程保持一致，降低返工成本。

## 1. 适用范围
- 适用于仓库根目录下全部 Java 微服务模块（如 `peach-auth`、`peach-monitor`、`peach-fileservice`、`peach-setting`、`peach-message`、`peach-gateway` 等）。
- 生成代码优先遵循本规范；若与现有代码冲突，以“保持现有模块风格一致”为最高优先级。

## 2. 技术基线（必须遵守）
- JDK：`1.8`。
- Spring Boot：`2.7.x`。
- Spring Cloud：`2021.0.5`。
- Spring Cloud Alibaba：`2021.0.5.0`。
- 禁止生成 Java 9+ 语法（如 `var`、`List.of`、文本块等）。

## 3. 模块与分层规范

### 3.1 模块结构
- 微服务模块按以下子模块拆分：
  - `*-entity`：DO/DTO/QO/VO 等数据对象。
  - `*-common`：模块通用常量、枚举、工具。
  - `*-service`：业务实现层、DAO、配置。
  - `*-rest`：内部 HTTP 接口。
  - `*-rest-external` 或 `*-openfeign-external`：对外服务间调用接口。
  - `*-launch`：启动类、健康检查、运行期入口。

### 3.2 包路径
- 根包固定为：`com.peach.<module>`。
- 常见包：`rest`、`service`、`service.impl`、`dao`、`config`、`entity`、`dto`、`qo`、`vo`、`constant`、`enums`。
- 禁止跨模块复制包名（例如 monitor 模块出现 userservice 包路径）。

## 4. 命名规范

### 4.1 类命名
- Controller：`XxxController`。
- Service 接口：`IXxxService` / `IXxxRuntimeService`。
- Service 实现：`XxxServiceImpl`。
- DAO：`XxxDao`。
- Feign 客户端：`XxxFeignClient` / `XxxFeignClients`（沿用已有模块习惯）。
- 配置类：`XxxConfig` / `XxxConfigure`。
- 常量类：`XxxConst`、`XxxConstant`，或 `interface` 常量定义（沿用现有方式）。

### 4.2 数据对象命名
- 持久化对象：`XxxDO`。
- 入参对象：`XxxDTO`。
- 查询对象：`XxxQO`。
- 出参对象：`XxxVO`。

### 4.3 方法与变量
- 方法名：小驼峰，动词开头，如 `login`、`snapshot`、`selectById`。
- 变量名：小驼峰，语义明确，禁止 `tmp`、`obj`、`data1` 等弱语义命名。
- 常量名：全大写下划线，如 `USER_SERVICE`、`FILE_PATH_SERVICE`。

## 5. 接口定义规范（Controller / OpenFeign）

### 5.1 Controller 规范
- 必须使用：`@RestController`、`@RequestMapping`。
- 必须补充 OpenAPI 注解：`@Tag`、`@Operation(summary = "...")`。
- 参数必须显式注解：`@PathVariable`、`@RequestParam`、`@RequestBody`、`@RequestPart`。
- 统一返回 `com.peach.common.response.Response`（文件流下载场景可返回 `ResponseEntity<StreamingResponseBody>`）。

### 5.2 路由约定
- 内部接口：`/xxx`、`/xxx/common` 等模块内部路径。
- 外部服务调用接口：统一放在 `rest.external`，路径建议 `/<service>/external/...`。
- 新增接口时，优先增量新增路径；禁止无必要修改已有路径语义。

### 5.3 OpenFeign 规范
- 必须通过服务名常量和路径常量声明：
  - `ServiceNameConstant`。
  - `ServicePathConstant`。
- 每个 Feign 方法参数必须带 Spring MVC 注解，避免隐式绑定。
- Feign 仅依赖 external/openfeign 模块，不直接依赖他服务内部实现。

## 6. 响应与异常规范

### 6.1 统一响应
- Controller 层优先使用：
  - `Response.success(data)`
  - `Response.success()`
  - `Response.fail(msg)`
  - `Response.businessResponse(msg)`
- 状态码语义统一通过 `StatusEnum` 管理，不在业务代码硬编码状态码字符串。

### 6.2 异常处理
- 业务异常使用 `BusinessException` / `LockException` 等已定义异常。
- 禁止吞异常；至少记录 `message + stacktrace`。
- 全局异常由 `GlobalExceptionHandler` 兜底，Controller 不直接返回裸异常信息。

## 7. 常量、枚举与配置规范

### 7.1 常量定义
- 通用常量放 `peach-common`（如编码、布尔语义、服务名、服务路径）。
- 模块私有常量放本模块 `common/constant` 包。
- 禁止在业务代码中直接写“魔法值”（路径、状态、编码、固定字符串）。

### 7.2 枚举定义
- 状态、类型、策略优先使用枚举（如 `StatusEnum`）。
- 枚举字段最少包含“编码 + 描述”（例如 `code` + `message`）。

### 7.3 配置类
- 放置在 `service.config` 或 `launch` 对应配置目录。
- 配置类只做 Bean/框架配置，禁止写业务流程代码。

## 8. DAO 与 MyBatis 规范
- DAO 接口统一 `extends PeachDao<DO, VO/DO>`。
- DAO 接口必须标注 `@MybatisDao`，保持与当前扫描机制一致。
- Mapper XML 规范：
  - `namespace` 必须与 DAO 全限定名一致。
  - 复用 SQL 片段（`allColumn`、`allColumnAlias`、`allColumnCond` 等）。
  - 表字段使用数据库命名，别名映射到 Java 小驼峰字段。
- 新增 SQL 优先复用已有通用方法，避免重复造轮子。

## 9. 日志与可观测性规范
- 统一使用 `@Slf4j`。
- 日志分级：`info`（关键流程）、`warn`（可恢复异常）、`error`（失败）。
- 日志中禁止输出密码、token、密钥、完整隐私数据。
- 健康检查接口保持轻量、可用、无副作用。

## 10. Codex执行清单（必须自检）
1. 包路径是否在正确模块下，未发生跨模块污染。
2. 命名是否符合 `Controller/Service/DO/DTO/QO/VO/Constant` 规范。
3. Controller 是否补齐 `@Tag/@Operation` 且参数注解完整。
4. 返回体是否统一 `Response`（下载等特例除外）。
5. 常量与状态码是否复用已有 `Const/Constant/Enum`。
6. Feign 是否使用服务名常量 + 路径常量。
7. 是否存在 Java 8 不兼容语法。
8. 异常是否交由全局异常处理，且日志完整。
9. Mapper XML 的 namespace、字段别名、条件片段是否规范。
10. 是否避免无关重构和接口破坏性变更。

## 11. 禁止事项
- 禁止引入与当前任务无关的大规模重构。
- 禁止随意修改已有接口 URL、返回结构、常量值语义。
- 禁止新增重复常量、重复枚举、重复工具类。
- 禁止绕过 common 模块定义重复实现统一能力。

## 12. 说明
- 本文档用于约束 Codex自动实现功能时的默认行为。
- 若某模块已有特殊约定，需在该模块 README 或 doc 中补充“模块例外规则”，并在实现时优先遵循。
