# Security And Quality Gates

本规则是代码任务的强制质量门禁。安全、数据保护和可验证正确性高于存量代码风格；历史实现只能作为兼容性证据，不能作为复制缺陷的理由。

## Rule Levels

- `REQUIRED`：安全、兼容性、模块边界和数据一致性要求，必须满足。
- `PREFERRED`：新代码目标风格；没有兼容性阻碍时采用。
- `LEGACY_COMPATIBLE`：只为局部修改存量代码而保留，不扩散到新模块。
- `FORBIDDEN`：即使相邻代码存在也不得复制。

冲突顺序：用户最新要求 > 安全与正确性 > `AGENTS.md` > `.codex/rules/` > 命中 skill > 模块局部风格 > 历史存量代码。

## Sensitive Data

`FORBIDDEN`：

- 在日志、操作审计、异常、README、测试快照中输出密码、token、secret、私钥、签名 URL、身份证号或完整敏感请求。
- 在 `@UserOperLog` 等 SpEL 表达式中直接记录完整 DTO，例如 `#p0`、`#request` 或对象 `toString()`；只允许记录经过确认的非敏感字段白名单。
- 让返回模型继承或携带密码、密钥、认证凭据等持久化字段后直接序列化。
- 把真实凭据写入源码、配置、MCP 记忆或示例。

`REQUIRED`：

- 修改 DTO、DO、VO、日志表达式和序列化配置时，逐项检查敏感字段的数据流。
- 用户、认证、支付、存储、消息载荷等高风险模型优先使用显式响应字段；无法立即消除存量继承时，必须显式排除敏感字段并报告剩余风险。
- 日志记录业务标识、结果、耗时和必要元数据，不记录完整报文。

## Correctness Before Imitation

- 发现相邻代码存在错误日志级别、无效注解、敏感字段泄露、事务失效、资源未关闭或并发风险时，不得以“保持风格”为由复制。
- `@Slf4j`、`@Indexed`、事务、缓存、校验等注解按实际用途添加，不为整齐而机械堆叠。
- 存量命名、路由和模型继承属于 `LEGACY_COMPATIBLE`；新公共 API 应先确认目标设计，避免扩大技术债。
- 示例代码必须能与当前 Java 21、Spring Boot 3.5.4 和模块依赖编译匹配。

## Completion Gates

代码改动完成前按风险执行：

1. 运行 `node scripts/check-utf8.mjs`，确认所有受版本控制及未忽略文本均为 UTF-8 无 BOM且无已知乱码标记。
2. 运行受影响模块编译或测试；公共模块、生成器、starter 和跨模块签名改动应扩大验证范围。
3. 检查 `git diff --check`，确认没有空白错误。
4. 复核变更范围、敏感数据、DAO/XML 对应关系、Java 21 兼容性和未提交用户改动。
5. 无法运行某项门禁时，在最终回复中说明原因、未验证范围和残余风险，不得写成“已验证”。

## Encoding Gate

- 所有文本文件必须是严格 UTF-8 且无 BOM；禁止 UTF-16、GBK、系统默认编码和 UTF-8 BOM。
- 禁止使用未显式指定 UTF-8 的脚本整文件读写中文内容。
- 终端乱码只作为诊断信号；必须先通过严格解码判断文件本体，再决定是否修改。
- 编码修复只允许移除 BOM 或在确认原始编码后做可审计转换，不得用替换字符覆盖无法解码的字节。

## Authorized Outputs

- 密码原文、密码哈希、私钥及服务端 secret 不作为普通业务响应输出。
- 登录 token、短时签名 URL、授权查看的个人字段可通过专用契约返回；验证调用方/资源权限，限制字段及凭据有效期，禁止复用含内部凭据的持久化对象。
- 合法返回不等于允许日志、审计、异常或测试快照记录该值；测试使用合成值并验证泄露边界。

## Authentication And Consistency

- 新增或实质修改密码存储/验证时采用经确认的自适应密码哈希；Base64、RSA 传输加密、可逆加密或普通快速摘要不替代密码哈希。已有格式迁移明确兼容路径，不擅自批量改库。
- 后端独立验证资源权限与租户隔离；菜单/按钮隐藏不构成后端授权，缓存存在也不等于有权限。
- 数据库事务不能回滚对象存储、邮件或 MQ。组合写流程明确失败结果、幂等标识、提交顺序、补偿/恢复责任，避免将长外部 I/O 无条件包入数据库事务。
- 可靠投递验证业务与 Outbox 写入原子边界、持久化恢复、并发领取和消费幂等；afterCommit 只改变执行时机，不保证进程故障后的可靠执行。
- 权限/缓存更新处理提交与回滚顺序、旧状态覆盖及多实例失效；根据实际一致性需求选择方案，不机械加入 MQ。

## Verification By Change

| 改动 | 最小相关证据 |
| --- | --- |
| Markdown / Rules / Skills | UTF-8、diff、引用路径、冲突及场景静态复核；不因文档编辑运行全项目构建 |
| Java / XML | 受影响编译或测试；SQL 映射/事务/授权变化增加对应行为验证 |
| starter / SPI | 条件装配、覆盖、失败和资源场景，细则见 `10-architecture-and-starters.md` |
| 前端 | 实际存在的类型/构建脚本；路由、身份和异步交互变化补行为检查 |
| 生成器 | 模板与隔离生成结果联动验证 |

缺陷修复优先添加能复现缺陷的回归测试；注释、格式及低影响等价整理不机械新建测试。不要写只断言内部调用或复制实现逻辑的测试。`-DskipTests package`、IDE 无报错、diff 和 UTF-8 分别不能替代行为测试。命令成功但未发现测试时不得宣称测试通过。
