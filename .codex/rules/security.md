# Security Rule

适用于代码、配置、日志、文档、测试和 Agent 输出。

- 禁止提交或输出 password、token、secret、private key、credential、签名 URL、身份证号等敏感数据；示例使用明显占位符。
- 日志和审计只记录完成诊断所需的非敏感字段，禁止整对象序列化式日志。
- 文件/对象路径必须防止 traversal、绝对路径逃逸和越权对象访问。
- 外部 URL、回调、下载地址和代理请求需要考虑 SSRF、协议白名单、地址白名单及超时。
- 数据库写入使用参数绑定；批量删除、通配扫描、管理操作必须有范围、权限和审计边界。
- 反序列化、模板渲染、脚本执行、动态类/组件加载必须限制允许类型或资源范围。
- 分布式锁、缓存、MQ 幂等不能替代数据库唯一约束、事务或业务状态校验。
- GitHub、数据库、外部系统的写操作必须符合用户授权和最小权限原则。
